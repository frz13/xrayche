# XrayHub — стабильный старт TUN (frz)

Изменены: `Services/XrayCoreService.cs`, `MainWindow.xaml.cs` (только цикл запуска).

## Причина (по логу в репозитории)
В TUN-режиме приложение писало «Соединение активно» уже после проверки через локальный SOCKS,
хотя адаптер ещё не был создан. Примерно через 10–15 с Xray падал:
`Timed out waiting for device query` → `Failed to setup adapter ... 0xB7` → код выхода -1 → «Соединение прервано».
Повтор из прошлого патча не срабатывал, потому что падение случалось уже ПОСЛЕ успешной проверки SOCKS.

## Что сделано
- TUN: успех объявляется только когда Xray написал `core: Xray ... started` ИЛИ адаптер реально поднялся (Up + нужный IP). Ожидание до 30 с.
- Если Xray упал/адаптер не создан — процесс чистится и запуск повторяется автоматически, до 3 попыток (раньше 1).
- Режим «Прокси» не затронут.

Не компилировалось (в среде нет .NET SDK). Сборка — через GitHub Actions (Build XrayHub) после коммита.

## Дополнение: очистка перед запуском TUN
Перед стартом Xray в TUN-режиме (`PrepareTunAsync`):
- завершается «осиротевший» xray.exe из этой же папки core (остался после краша прошлого запуска и держит адаптер);
- если адаптер с именем TUN уже виден, либо это первый запуск за сессию, либо прошлый старт TUN упал — удаляются остатки адаптера (pnputil /remove-device, затем Remove-NetAdapter). Ошибки очистки только пишутся в лог и подключение не блокируют.
На обычном быстром пути (адаптера нет, прошлый старт успешный) PowerShell не запускается.
Не проверялось на реальной Windows.
