# XrayHub 0.3.4 — обновление приложения

Этот архив содержит только файлы приложения. В нём намеренно нет `.github` и workflow. Существующий `build-windows.yml` не меняй.

1. Распакуй ZIP.
2. Загрузи все файлы архива в корень существующего репозитория, сохранив структуру каталогов и заменяя старые файлы.
3. Не удаляй и не заменяй `.github/workflows/build-windows.yml`.
4. Сделай Commit changes и проверь GitHub Actions.

## Изменения

- Убран DoH URL fallback: для стандартных профилей и импортированного JSON используется один выбранный DNS IP, по умолчанию `8.8.8.8`.
- Проверка серверов: ICMP ping, если ICMP недоступен — TCP connect к порту профиля с пометкой `TCP`.
- JSON-профили также проверяются, если endpoint можно извлечь из `outbounds`.
- Задержка отображается синим рядом с протоколом и информационной кнопкой.
- Для трея загружается тот же встроенный округлённый ICO-ресурс, что и у приложения.
- Пункт трея обновляется после импорта/удаления профилей; «Подключиться к последнему серверу» использует последний сохранённый выбор.
- Уведомления остаются внутри главного окна; модальные MessageBox не используются.
- У старого логотипа изменены только внешние углы чёрной подложки; X и `ray` не перерисованы.

## Примечание о TCP/IP стекe

В release notes V2RayTun Windows упоминается настройка gVisor stack. Документация Xray TUN не содержит свойства `stack` в JSON inbound. Чтобы дать настоящее переключение system/gVisor/mixed, XrayHub нужен отдельный TUN/backend, а не только элемент интерфейса.
